## 已修复问题

1. 管理端 `useTableQuery` 记录草稿代次及自己提交的查询。旧查询完成时不再取消更新的输入，也不把表单回填成旧条件；翻页、重置与外部 URL 导航继续取消此前防抖。使用 location.key 消费同 URL 的重新导航，避免残留提交标记。
2. 收藏通过 `PostCard.onFavoritePendingChange` 在变更请求开始时中止分页，并以同步 Set 阻止变更期间再分页；失败解除锁并保留原项，成功后按剩余项继续读取。对其他页面删除游标导致的空尾页，最多追加一次首屏复核并替换失效列表；首屏复核失败保留错误重试入口，不把结果缺失误判为收藏耗尽。
3. 评论首屏/点赞回填按 ID 合并到已展开的回复，不再截断尾页。分页游标独立记录服务器原始页末项，避免本地插入或字段回填改变游标；回复提交结果也去重。
4. “我的作品”按每次成功 action 推进分页版本，重新建立已重验证的首屏并取消旧页面请求，覆盖删除或重新提交位于尾页的情况；失败 action 不重置已加载分页。成功操作会回到重新建立的列表位置，这是本次明确采用的刷新策略。
5. 用户编辑与角色权限编辑为每次保存保留请求身份；关闭、主体切换及卸载使身份失效。旧成功/错误/finally 不再关闭新表单、覆盖新草稿或解除新请求的忙碌状态。保存期间禁止修改表单并阻止重复提交；失败保留草稿与重试。即使编辑会话已结束，已确认成功的服务器写入仍使共享角色缓存失效并触发列表重验证。

## 新增回归

用户端 `scripts/review/regressions.mjs` 与两份 `*-fixes.jsx.txt` 使用真实组件、真实作品 action、可控路由 loader 和合成 fetch 响应，新增 11 项时序回归：

- 查询 A 未完成时输入 B，先完成 A，B 草稿保留且最终发出 B 请求。
- 外部 URL 导航取消旧防抖。
- 点赞回填保留已展开回复及完成状态。
- 收藏 DELETE 响应晚于空分页时仍能继续读取。
- 收藏删除失败解锁并保留原项。
- 缺失收藏游标触发一次首屏复核。
- 尾页作品删除成功刷新列表并拒绝旧分页。
- 删除失败保留尾页，原分页可正常完成。
- 用户 A 的旧保存成功不影响用户 B 草稿。
- 当前用户保存失败后可修改重试，成功正常关闭。
- 旧角色保存成功不影响新角色权限草稿。

`run.mjs` 保留原有 19 项回归，新增回归入口使用 StrictMode，所有生产组件通过与项目一致的 React Compiler。测试脚本显式从各仓依赖目录解析 Babel preset/plugin，并规范化临时目录真实路径以兼容 macOS 的 /var → /private/var。只需传入 `regressions` 可单跑新增组；默认执行全部三组。
